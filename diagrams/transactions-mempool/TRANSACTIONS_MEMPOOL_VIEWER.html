Key Features of Transaction System

1. Transaction Structure & Lifecycle

Key Concepts

  • Transaction Object: Contains content, signature, hash, status, blockNumber
  • Content: All transaction data (from, to, amount, gcr_edits, nonce, etc.)
  • Hash: SHA256 of JSON.stringify(content)
  • Signature: Cryptographic signature of hash
  • Dual Signature: PQC signature with optional ed25519 backup
  • Lifecycle: Create → Sign → Broadcast → Validate → Mempool → Consensus → Finalize

2. Transaction Creation & Signing

Key Concepts

  • Content First: All fields filled before hash calculation
  • SHA256 Hash: Deterministic hash of stringified content
  • Algorithm Selection: ed25519, ml-dsa, or sl-dsa
  • Backup Signature: PQC txs can include ed25519 signature of hash
  • Nonce Requirement: Must fetch current nonce from GCR
  • Timestamp: Date.now() for transaction ordering

Transaction & Mempool Principles

  1. Multi-Algorithm Support: Ed25519, ML-DSA, SL-DSA with dual signature option
  2. Hash Integrity: SHA256 of content must match tx.hash
  3. Signature Verification: Two-step validation process
  4. Nonce Sequencing: Sequential nonce must increment by 1
  5. Block Assignment: Based on consensus state
  6. Mempool Merging: Phase 3 merges all shard mempools
  7. GCREdit Execution: Phase 4 applies state changes
  8. Timestamp Ordering: Transactions ordered by timestamp
  9. Duplicate Prevention: Hash uniqueness checked
  10. Rollback Support: Automatic on block failure
